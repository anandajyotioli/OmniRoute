- **fix(relay):** minting a relay token (`POST /api/relay/tokens`) now requires a signed-in dashboard session or the local CLI, so an API key — even a manage-scoped one — can no longer create new relay credentials; listing, editing and revoking keep accepting a manage key. A malformed request body now answers `400 Invalid JSON body`, and an unexpected failure answers a sanitized `500` instead of echoing the raw exception message.
